        How to use this panel
        

        The panel runs on this machine only. It never ships with the site and it never writes outside the project folder.
        


        

        Start the panel
        

        Double click tools\admin\start-admin.cmd. It starts the server and opens this page for you. Keep the window open while you work; close it, or press Ctrl+C, to stop the server.
        

        From a terminal npm run admin does the same. It first asks the port whether a helper is already running. If one is, it only opens this page again, which is the way back after the tab was closed by accident. If none is, it starts the helper and opens the page.
        

        The helper stops itself after 45 minutes without a request, so a forgotten window does not hold the port. The Disconnect server button at the top of the panel stops it right away when the work is finished, and npm run admin brings it back.
        

        The panel needs the built site, so run npm run build once before the first use. The red banner at the top appears when the build is older than the sources, and it turns off the buttons that write. A failed build looks the same, so read the banner before you write.
        

        


        

        The four views
        

        

        Visual inspector
        

        Shows the built site in a frame. Click an element to see the rule that draws it, change the values, and save them into the stylesheet. The export box shows the same change as text, so the file can also be edited by hand.
        

        Content editor
        

        Writes the markdown entries of the blog and the words sections. This is the source of the site, not the site itself.
        

        Deploy panel
        

        Opens the connection to the webspace and sends the release. This is the only part that touches the live site.
        

        How to use
        

        This page.
        

        

        The tabs work with the arrow keys. The left and right arrows move between them, Home and End jump to the first and the last.
        

        


        

        Writing an entry
        

          

        1. Open the Content editor and pick the section from the list. Only the sections that carry entries are in the list.
          2. 

        2. Press Add new entry. The title becomes the file name, so a clear title gives a clear address.
          3. 

        3. Fill in the title, the date and the markdown. The excerpt, the standfirst and the author note are optional.
          4. 

        4. Watch the Index card preview while you type. It shows the card the build will render.
          5. 

        5. Press Write the entry and rebuild. The markdown file is written into content/ and the site is rebuilt straight away.
          6. 

        6. Press Save for later instead to keep the text in content/drafts/. The build never reads that folder, so a draft never reaches the site.
          7. 

        

        The entry only goes live after a publish in the Deploy panel. The rebuild in the editor builds the site on this machine; it does not send anything to the webspace.
        

        


        

        The markdown rules
        

          

        • The page owns the H1, so the body starts at H2. A level one heading in the body stops the build.
          • 

        • Every image needs a description, because the description becomes the alt text. ![A short description](assets/pictures/name.webp "800x450")
          • 

        • The date must be a real day in the yyyy-mm-dd form.
          • 

        • The excerpt replaces the first forty five words on the index card. Without one, the build cuts the body at forty five words.
          • 

        

        


        

        Publishing a release
        

          

        1. Fill in the host address, the user name and the password of the webspace. The folder is /home/www/annoyinggoods. The password stays in the page and is never written to a file.
          2. 

        2. Press Check connection first. It opens the session, prints the banner and the target folder, and transfers nothing.
          3. 

        3. Press Publish to IONOS. The helper runs the whole gate first: the type check, the build, the test suite and the packaging. Nothing is uploaded while the gate is red.
          4. 

        4. Press Fix server permissions afterwards. It sets the folders to 755 and the files to 644. A page that renders unstyled is almost always this problem.
          5. 

        

        Every publish keeps a snapshot of the release in dist/snapshots/, so a bad publish can be undone by publishing the snapshot folder again.
        

        The test suite needs a free port. Port 8000 is the default, and another program on this machine may already hold it, so the helper picks a free port on its own. The port it used is named in the server reply.
        

        


        

        When something does not work
        

          

        • The red banner is up. The build is older than the sources. Run npm run build, or let the panel rebuild, and the banner clears on its own.
          • 

        • The publish fails at the test step. The gate ran the type check and the build, so the tests are the reason. The server reply names the failing test.
          • 

        • The publish fails at the upload. The host, the user name, the port or the folder is wrong. The check mode prints what the server says about the folder.
          • 

        • An entry does not appear on the site. It is still a draft, or the page needs a publish.
          • 

        • The panel says the helper is not running. Start it with tools\admin\start-admin.cmd, or with npm run admin, which opens this page again. The export boxes still work without it.
          • 

        • The helper stopped on its own. It stops after 45 minutes without a request. Run npm run admin to start it again.
