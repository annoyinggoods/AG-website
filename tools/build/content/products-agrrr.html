What is this?

Building a website can be a pain. It can be AGRrrevating. It can really make you go

“GRrrr!”

AGrrr! is a desktop website builder for people who want to decide how a page looks without hand-writing every line of code. Arrange prepared blocks on a live canvas, edit your content, and export ordinary website files you can host yourself. AI is optional, not the starting point.

You need to growl no more- we've got you!

For the Non-Technical Reader

A website is made from files that a browser reads to display pages. A website builder helps you create those files without writing all of the code yourself. In AGrrr!, you place ready-made blocks—such as headers, image rows, buttons, and forms—on a live page, arrange them, and add your own words. The canvas is a real render, not just a sketch.

When you are happy with the result, AGrrr! exports HTML, CSS, and JavaScript files. Put them on hosting you already have, or deploy them to your host through the app. Projects stay on your computer while you work; no account or AI is required. The block library has more than 1,200 prepared items. If you connect AI, you bring your own provider key, and suggestions wait for your approval.

AGrrr! is for people who want hands-on control without becoming front-end developers. It is not a prompt-only generator or a full developer IDE. The current Windows build is early, with style breadth and accessibility polish still being improved.

A Bit More Technical

AGrrr! composes multi-page websites from validated HTML, CSS, and JavaScript blocks on a live-rendering canvas. Its 18-token theme system applies consistent styling across pages. Layouts use viewport units, and the responsive engine proposes behavior for smaller screens; export waits for outstanding decisions to be resolved.

Compilation produces plain website files plus deployment support files. Supported forms and other server-side features can use generated PHP handlers for ordinary shared hosting, with SQLite locally during authoring. Projects are local. Optional AI uses a user-configured provider, with diff-based suggestions accepted or rejected by the user. Deployment goes to hosting the user owns over FTP or SFTP.

This is RC (Release Candidate) for version 1 stable. Bugs can happen and development is ongoing, but underlying code is solid and tested enough that no breaking bugs and compatibility issues with future releases are expected.

Fully Technical

AGrrr! is a Windows desktop visual web composer. Projects consist of page compositions and local metadata. The live canvas renders real web layout while the user places and edits blocks. The searchable library contains 1,200+ pre-validated HTML/CSS/JavaScript records; user-authored content can be saved as library entries. Themes use an 18-token schema with dark/light sets and custom properties. Canvas instrumentation supports viewport measurements; responsive scaling proposals are evaluated element by element and unresolved proposals block export.

The compiler emits deterministic plain HTML, CSS, and JavaScript, plus .htaccess, robots.txt, 404 page, and handover README. Multi-page navigation is derived from project pages. Supported server-side handlers compile to PHP for shared hosting, with SQLite for local authoring. Consent-banner compile gates defer non-essential scripts until consent.

AI is optional and uses user-owned keys for supported providers or a local OpenAI-compatible endpoint. Keys remain in the application backend. Reviews produce diffs that require per-change acceptance; AI does not generate the site from scratch or modify work without confirmation. Projects remain local; network access is for configured model calls or explicit deployment to user-owned hosting. AGrrr! is in an early Windows release; style breadth and accessibility polish remain in progress.

The loop, tooth to tail

The whole loop runs on your desktop, in one window, from blank page to uploaded site.

One pass, six bites

  1. Open a blank page and drag elements onto the canvas. Nest them, resize them, move them. The live render keeps you honest.
  2. Raid the library: more than 1,200 pre-written, pre-validated blocks — heroes, forms, timelines, menus, effects — searched offline and dropped in with your own words in the parameters.
  3. Set the look once with the 18-token theme system, and every page inherits it. Clone a page, spin off subpages, and the site stays consistent without you policing it.
  4. Look at the code whenever you want. A real code editor sits beside the canvas, and the boundary between what you own and what the canvas owns is explicit, not guessed.
  5. Go small-screen. The scaling engine proposes how each element should behave on a phone or tablet, you answer each proposal, and the app refuses to export while a decision is still open.
  6. Export or deploy. Take single files or the whole site, with the delivery files a shared host needs — sitemap, robots, a 404 page — and upload straight to your hosting over FTP or SFTP. The deployed site is the same bytes as the exported one.

What you throw in, what you get back

Throw in typed text, library blocks, or code you paste by hand. Highlight anything you write in the editor and it can be saved into your own library as a first-class block, passing the same validation gate as everything else. Point it at a page you admire and it lifts that page's design tokens into a theme for you.

You get back real code, plain warnings when something cannot survive the compile, and a handover README that says exactly what the app cannot know about your host — no pretending the receipt is the work.

The session opens: pages and dress code

The growl is optional

AGrrr! ships with no bundled model and no mandate to use one. The canvas, the library, the compiler and the export all work with zero providers configured — that is not a degraded mode, it is the floor, and it is deliberate.

Bring your own brain

If you want a model looking over your shoulder, plug in a key from Anthropic, OpenAI, Gemini or OpenRouter, or point the app at a model running on your own machine through the OpenAI-compatible adapter. The key is kept in the app's own backend and never enters the page it is reviewing.

It proposes, you decide

The model reviews in the background — after ten new lines or a minute of quiet, and never while you are typing. Its suggestions arrive as diffs you accept or reject, one by one. It never generates your site from scratch, and it never lays a paw on your work without your confirmation.

Every growl is kept

Version history is append-only. Name a version and it is permanent, the newest versions survive any amount of thrashing, and the first snapshot of every session is never discarded. The messy first pass stays reachable until you have tamed it.

Who it is for

You, probably, if this stung a little

You already have a domain and hosting, you want a presentable page, and you do not want to design in the abstract or be told what to build by a prompt box. You would rather place a block, see it render, and get on with your life. If you have never built anything at all, start with the step-by-step guide instead of this page — it assumes nothing.

It is not a developer IDE, and it is not a generator that takes your sentence and runs. If you want either of those, the world is already full of them.

Where it stands

The release candidate for version 1

The Windows build you can download today is 0.9.0 — the release candidate for version 1 stable. Bugs can happen and development is ongoing, but the underlying code is solid and tested enough that no breaking bugs or compatibility issues with future releases are expected: a site you build on 0.9.0 is a site version 1 opens.

The engine, the canvas, the snippet library, the code editor, the optional model layer, theming, multi-page, import, the responsive scaling engine and the PHP backend with deployment are built and tested — thousands of automated tests across the app and its backend hold the pieces together, and the full surface sweep runs green against the packaged build. What remains is the last stretch: style breadth and accessibility polish.
